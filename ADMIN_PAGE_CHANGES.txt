1. THE PROBLEM
--------------------------------------------------------------------------------

A "Settings" page had been built for the admin panel, holding nine tools
(Scraper Control, Property Manager, Property Sync, Feature Toggles, Promo
Cards, SMS Devices, Affiliate Tracker, Affiliate Config, Link Manager), but
admins could not find it anywhere in the admin panel.

Root cause: the page existed and its URL worked, but nothing linked to it.

  What existed                                      Status before the fix
  ------------------------------------------------  ---------------------
  Page component   admin.settings.jsx               Present, working
  Route            /admin/settings  (App.js)        Present, admin-protected
  Landing card     LandingAdminPage.jsx adminCards  MISSING
  Sidebar link     shell/adminNav.js ADMIN_NAV      MISSING

Because both navigation entry points were missing, the only way to reach the
page was by typing  /admin/settings  into the address bar.


--------------------------------------------------------------------------------
2. HOW ADMIN NAVIGATION WORKS (for future changes)
--------------------------------------------------------------------------------

The admin panel has TWO separate navigation lists. A new admin page must be
added to BOTH, plus a route, or it will be partly or fully invisible.

  (a) Route — client/src/App.js
      All admin pages sit inside  <Route path="/admin" element={<AdminLayout />}>
      and are wrapped in  <AdminProtectedRoute>  so only admins can open them.
      The page component is lazy-loaded at the top of App.js, e.g.:

        const AdminSettings = lazy(() => import("./screens/Admin Page/admin.settings"));
        <Route path="/admin/settings"
               element={<AdminProtectedRoute element={<AdminSettings />} />} />

  (b) Landing page cards — client/src/screens/Admin Page/LandingAdminPage.jsx
      The  adminCards  array drives the grid of cards on /admin/Landingpage.
      Each card is:
        { id, title, description, icon (lucide-react), route, color, gradient }

  (c) Sidebar / mobile drawer / command palette —
      client/src/screens/Admin Page/shell/adminNav.js
      ADMIN_NAV is the single source for the left rail, the mobile drawer
      and the search palette (via ADMIN_NAV_ITEMS). It also drives the
      breadcrumb label (adminCrumb). Items are grouped:
        Overview, Listings, People, Leads, Marketing, Money, System
      Each item is:
        { id, label, route, icon }
      An optional  permission  field is read by AdminLayout for future
      super-admin roles; nothing uses it yet.

4. WHAT THE SETTINGS PAGE CONTAINS
--------------------------------------------------------------------------------

File: client/src/screens/Admin Page/admin.settings.jsx
URL : /admin/settings

A header ("Settings — Manage platform features, promotions, and communication
channels") and a scrollable row of tabs. Each tab lazy-loads its own screen,
so a tab's code is only downloaded when it is opened. Default tab: Scraper
Control.

  #  Tab label          Tab id            Component file
  -  -----------------  ----------------  ---------------------------------
  1  Scraper Control    scraper           admin.scraperControl.jsx
  2  Property Manager   properties        admin.propertyManager  (see 5.1)
  3  Property Sync      propertySync      admin.propertySync.jsx
  4  Feature Toggles    toggles           admin.featureToggles.jsx
  5  Promo Cards        promos            admin.promos.jsx
  6  SMS Devices        sms               admin.smsDevices.jsx
  7  Affiliate Tracker  affiliates        admin.affiliateTracker.jsx
  8  Affiliate Config   affiliateConfig   admin.affiliateConfig.jsx
  9  Link Manager       linkManager       admin.linkManager.jsx

To add a tab: create the component, lazy-import it at the top of
admin.settings.jsx, and add an entry to SETTINGS_TABS:
  { id: "...", label: "...", icon: <lucide icon>, component: <Component> }

5. KNOWN ISSUES FOUND (NOT CHANGED)
--------------------------------------------------------------------------------

5.1  New Property Manager is shadowed by the old one
     Two files exist side by side:
       admin.propertyManager.js   (original, from the initial upload)
       admin.propertyManager.jsx  (newer "professional" version, commit 5b8e7bf)
     Both App.js and admin.settings.jsx import  "./admin.propertyManager"
     without an extension. Create React App resolves .js before .jsx, so
     BOTH /admin/propertymanager and the Settings → Property Manager tab load
     the OLD .js version. The newer .jsx is never used.
     Fix (when wanted): change the imports to  "./admin.propertyManager.jsx"
     or rename/remove the old .js file, then check the page.

5.2  Some pages appear twice
     Promo Cards, SMS Devices and Property Manager are each reachable both as
     their own page (/admin/promos, /admin/sms-devices,
     /admin/propertymanager) and as a tab inside Settings. This works, but
     the two entry points could be merged later to keep the menu shorter.

5.3  Landing page uses full page reloads
     LandingAdminPage.jsx navigates with  window.location.href = route
     instead of React Router's navigate(), so each card click reloads the
     whole app. Works, but slower than it needs to be.


--------------------------------------------------------------------------------
6. HOW TO CHECK
--------------------------------------------------------------------------------

  1. Sign in with an admin account.
  2. Open /admin/Landingpage — the "Settings" card (grey) is the last card.
  3. Click it — /admin/settings opens on the Scraper Control tab.
  4. In the left sidebar, under "System", "Settings" is listed and is
     highlighted while on the page; the breadcrumb reads "System › Settings".
  5. On a phone-width screen, open the menu drawer — Settings is listed.
  6. Click through all nine tabs to confirm each one loads.

Build: the client compiles with  npx react-scripts build . Neither change
produces new warnings.
