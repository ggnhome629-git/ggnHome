================================================================================
GGNHOME ADMIN PANEL - UI UPGRADE SPECIFICATION
================================================================================
Scope: every screen under client/src/screens/Admin Page/ and everything they do
today, redesigned into one consistent, professional, lively admin console.
No feature is removed. Gaps found in the audit are listed in PART 2 and
specified as additions where the backend already supports them (marked [API OK])
or would need new backend work (marked [NEEDS API]).

Design references used (Google Material 3, Stripe Dashboard, generic admin-UX
rules, real-estate moderation queues):
- Material 3 navigation rail: collapsed + expanded rail, 3-7 primary
  destinations, labels always shown with icons (icon-only rails are criticised
  as vague), rail for medium+ windows, bottom bar / drawer on small.
- Stripe dashboard: dense but calm tables, filter chips, summary metrics always
  visible with detail one level deeper, list -> detail flows, tabbed full-page
  views.
- Admin UX rules: visible search, removable filter chips, filters in URL,
  sortable tables, 10/25/50/100 page sizes with "Showing X-Y of Z", density
  toggle, three-state select-all checkbox, bulk bar with count, confirm dialogs
  naming the resource, soft delete + Undo toast, explicit empty/loading/error
  states, never a bare 403.
- Property moderation queues: card shows main image, code, price, title,
  address, type, owner, requested date so a decision needs no extra click;
  approve = one click with confirmation; status = Pending / Published / Expired.

 S1  /admin/Landingpage, /admin/usagetrack, /admin/usagetrack2, /admin/rewards,

UX / CONSISTENCY
 U1  Public TopNavigationBar on admin pages -> replace with admin shell.

 U3  Three different list idioms (cards, rows, tables). Standardise on one data
     table component with a card fallback on mobile.
 U4  alert()/confirm() used (preferences, agents, enquiries, sms). Replace with
     MUI dialogs + toasts.
 U5  Callback Requests is read-only: no way to mark In Progress / Resolved.
     [NEEDS API: PATCH /api/admin/callback/:id/status]
 U6  Enquiries: no search, filter, sort or export.
 U7  User Management: no search/filter/role change/export.
 U8  Property Manager filters only the current page (client-side) while stats
     are global -> filter server-side [NEEDS API: status/search params].
 U9  Property Manager has no affiliate/own-database distinction, no commission
     field, no approval queue view (isPostedNew / isEdited flags exist in the
     model but are not surfaced as "Awaiting approval" / "Edited - re-approve").

     Registration" actually registers agents; "ALL Properties" lives at
     /admin/rewardsproperties; page component PaymentsRewardsDashboard is the
     enquiries page. Fix labels and (optionally) route names with redirects.
 U11 admin.properties.js (pending payments approve/reject + distribute reward)
     has no route; its features (payment approval) are therefore unreachable.
     Re-home as "Payments" screen.
 U12 /admin/usagetrack2 is unlinked; merge with usagetrack into one
     "System & Usage" screen.
 U13 Duplicate fetchUser/handleLogout in ~12 files; move into the shell.
 U14 propertymanager.txt is a stale copy - delete.
 U15 Charts are CSS divs with no tooltips/axes; rewards "recently distributed"

PART 6 - ROLES: NORMAL ADMIN vs SUPER ADMIN (CHECKLIST PHASE 2)
================================================================================
Backend today has one role. UI should be built role-aware now.
 - useAdminUser() exposes { role: "admin" | "superadmin", permissions: [] }
   with permission strings "resource:action" (e.g. properties:approve,
   agents:suspend, system:usage, admins:manage, features:manage).
 - Nav and buttons render from a single config:
     { id, label, icon, route, permission, featureFlag }.
 - Normal admin sees: Dashboard, Listings, People (no admin management),
   Leads, Marketing, Money. Hidden/locked: Admin Access, Usage & Limits,
   SMS Phones, Feature Control.
 - Super admin extra screen "Feature Control" (matches checklist items 13 &
   15): table of platform features with toggles - e.g. Affiliate listings
   visible, Affiliate redirect, Rewards banner, Flatmates, Services, AI
   assistant, Price predictor, Promo placements - each with description,
   last changed by/at, and Save with confirmation. [NEEDS API]
 - Disabled-by-permission controls show tooltip "Requires Super Admin".
 - Mid-session loss of permission: contextual banner, never a bare 403.

PART 8 - CROSS-CUTTING BEHAVIOUR
================================================================================
8.1 Loading: skeletons matching final layout; never a blank page; buttons show
    spinner + disabled during requests; polling screens do not flicker.
8.2 Empty: illustration/icon, explanation, primary next step.
8.3 Errors: inline per widget, Retry, request id in details; 401 -> sign-in with
    return URL; 403 -> contextual explanation.
8.4 Confirmations: all destructive actions use ConfirmDialog; irreversible bulk
    deletes require typing the count.
8.5 Feedback: toasts for success; Undo for reversible; progress for >2s bulk.
8.6 URL state: filters, sort, page, tab, open drawer id in query string; back
    button works; links are shareable between admins.
8.7 Persistence (try/catch): rail collapsed, density, column visibility, saved
    views, theme, collapsed dashboard sections.
8.8 Keyboard: Ctrl/Cmd+K palette, / focus search, G then D/P/U/A navigation,
    Esc closes drawers/dialogs, J/K in queues.
8.9 Privacy: phones masked by default across admin; reveal is explicit and
    audit-logged; owner numbers never shown in text fields.
8.10 Performance: lazy-load routes (kept), virtualised long lists, debounced
    search, server pagination, cache dashboard 60s, cancel stale requests,
    image thumbnails sized.
8.11 i18n/format: Indian number grouping (en-IN), Rs symbol, Cr/L compact
    for sale prices, dates "12 Oct 2026, 4:30 PM", relative times with absolute
    tooltip.
8.12 Print/export: CSV on every table; dashboard PDF export.
8.13 Dark mode: all components themed; charts use dark palette.
8.14 Mobile: bottom sheet filters, card lists, FAB for primary action, drawers
    become full screen, sticky bulk bar at bottom.
8.15 Audit logging [NEEDS API]: approvals, deletes, role changes, reveals,
    reward sends - shown in drawer "Activity" tabs and an Audit Log page.
